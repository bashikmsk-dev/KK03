# Кибер Кино — сайт международного фестиваля ИИ-короткого метра

Статический сайт: HTML, CSS и обычный JS. Сборка **не обязательна** — файлы
самодостаточны, их можно просто открыть в браузере или положить на любой хостинг.
Для удобной разработки сверху подключён Vite (дев-сервер с автообновлением и
минифицированная сборка).

## Быстрый старт

Нужен [Node.js](https://nodejs.org) версии 20.19 или новее (проверить: `node -v`).
Работает одинаково на Windows, macOS и Linux.

```bash
git clone https://github.com/bashikmsk-dev/KK03.git
cd KK03
npm install
npm run dev
```

Откроется адрес `http://localhost:5173`. Правки в HTML, CSS и JS подхватываются сразу.

| Команда | Что делает |
| --- | --- |
| `npm run dev` | дев-сервер на `http://localhost:5173` |
| `npm run build` | минифицированная сборка в папку `dist/` |
| `npm run preview` | посмотреть собранный `dist/` на `http://localhost:4173` |

**Без Node.js.** Сайт открывается и так: скачайте репозиторий и откройте `index.html`
двойным кликом. Именно поэтому скрипты подключены как обычные, а не как ES-модули —
модули браузер по протоколу `file://` не загружает.

### Имена жюри внутри картинки

Имя каждого члена жюри выводится текстом прямо в белой плашке на его карточке —
это не часть изображения, а HTML. Положение плашки задаётся в `index.html`
и `en/index.html` тремя переменными в атрибуте `style` карточки:

```html
<div class="juror reveal" style="--img-w: 67%; --plate-y: 70.4%; --plate-w: 75%">
```

- `--plate-y` — центр белой плашки по вертикали, в % от высоты картинки;
- `--plate-w` — ширина текстового блока, в % от ширины картинки;
- `--img-w` — ширина самой картинки в колонке; стоит только у квадратных снимков,
  чтобы все карточки в ряду были одной высоты.

Если замените фото жюри на другое — поправьте эти три числа у нужной карточки.

## Эффект на титульном экране

Базово виден `enshtane-01.png`. При наведении курсора вокруг него остаётся «дыра», а вся
остальная площадь проявляется как `enshtane-02.png`.

Режим переключается одной строкой в начале `assets/js/hero.js`:

```js
const REVEAL_MODE = 'outside'; // 'outside' — 02 проявляется ЗА областью курсора
                               // 'lens'    — 02 виден только в круге ПОД курсором
```

Там же настраиваются размер круга (`REVEAL_RADIUS`, `RADIUS_MIN`, `RADIUS_MAX`) и
инерция движения (`EASE`). На телефонах и планшетах, где курсора нет, маска плавно
движется сама. При системной настройке «уменьшить движение» эффект отключается.

## Публикация на GitHub Pages

1. Settings → Pages → Source: **GitHub Actions**.
2. Влейте ветку в `main` — воркфлоу `.github/workflows/pages.yml` соберёт проект
   (`npm ci && npm run build`) и опубликует папку `dist/`.

Можно и без сборки: Source → **Deploy from a branch**, ветка и папка `/ (root)`.
Файл `.nojekyll` в корне уже лежит, сайт отдастся как есть.

## Публикация на Vercel

Проект собирается командой `npm run build`, папка публикации — `dist/`.

`vercel.json` задаёт заголовки кэширования: файлы в `/assets` собираются с хешем
в имени и кэшируются на год, а `/assets/js` копируется в сборку без хеша, поэтому
проверяется при каждом заходе — иначе после правки скрипта посетитель остался бы
со старой версией.

## Перенос на другой хостинг

Сайт — чистая статика, серверной части у него нет: ни Next.js, ни API-роутов,
ни баз. Поэтому переехать можно на любой хостинг, умеющий отдавать файлы по
HTTPS, — от виртуального хостинга с панелью до объектного хранилища с CDN.

```bash
npm ci
npm run build          # результат — папка dist/
```

**Выкладывается содержимое `dist/`** (именно содержимое, а не саму папку) в
корень сайта. Внутри уже лежит `.htaccess` для Apache и LiteSpeed — его кладёт
в сборку плагин `copyDeployFiles`. Для nginx готовый конфиг — в
`deploy/nginx.conf.sample`.

Что хостинг должен уметь — всего три вещи:

| Что | Зачем |
| --- | --- |
| `index.html` как индексный файл каталога | адрес `/en/` должен открывать `/en/index.html` |
| своя страница 404 → `/404.html` | иначе на несуществующих адресах будет страница хостинга |
| HTTPS | без него не работают `localStorage` и часть браузерных API |

Заголовки кэширования из `deploy/`-конфигов желательны, но не обязательны:
без них сайт работает, просто браузер будет чаще перекачивать картинки.

Чего делать **не** нужно: настраивать «красивые адреса» (все ссылки и так
явные, с `.html`), проксирование, перенаправления внутри сайта.

### Автоматическая выкладка

`.github/workflows/deploy.yml` делает то же, что раньше делал Vercel: на каждый
пуш в рабочую ветку GitHub собирает сайт и заливает `dist/` на хостинг по SSH
(`rsync --delete`, то есть устаревшие файлы с сервера убираются).

Нужно один раз добавить доступы в Settings → Secrets and variables → Actions:
`SPRINTHOST_HOST`, `SPRINTHOST_USER`, `SPRINTHOST_PATH` (корень сайта, тот, где
должен лежать `index.html`), `SPRINTHOST_KEY` (приватный SSH-ключ целиком) и,
если порт не 22, `SPRINTHOST_PORT`. Пока секретов нет, выкладка пропускается, а
сборка остаётся зелёной.

**В `SPRINTHOST_PATH` должен быть именно корень сайта.** `--delete` вычищает в
нём всё, чего нет в сборке: если указать домашний каталог, вычистит и его.

После переезда:

1. поменять домен в `site.config.json`, если он другой, и запустить
   `python3 tools/make_seo.py`;
2. проверить `/robots.txt`, `/sitemap.xml` и любой несуществующий адрес —
   должна открыться своя 404 с кодом 404;
3. в политике конфиденциальности поправить раздел «Где обрабатываются данные»:
   там указано, где физически стоят серверы сайта.

## robots.txt и sitemap.xml

Оба файла генерируются скриптом и лежат в `public/`, откуда сборка кладёт их в
корень сайта:

```bash
python3 tools/make_seo.py
```

Адрес сайта лежит в `site.config.json` в корне проекта — это единственное место,
где он записан. Оттуда его берут и этот скрипт, и сборка. **При переезде на другой
домен меняем адрес там и запускаем `python3 tools/make_seo.py` заново.**

В разметке страниц `canonical`, `hreflang` и `og:image` остаются относительными —
так страницы открываются и прямо с диска. Абсолютными их делает плагин
`absoluteSeoLinks` в `vite.config.js`: он же дописывает `og:url`. Делать это
обязательно: Open Graph требует абсолютных адресов, иначе мессенджеры не покажут
картинку в превью ссылки, а относительный `canonical` не спасает от дублей, когда
на сайт ведёт больше одного домена.

## Форма заявки

Форма живёт в конце страницы регламента (`#apply` в `rules.html` и
`en/rules.html`). Бэкенда у сайта нет: заявку принимает веб-приложение Google
Apps Script, привязанное к таблице организатора. Оно пишет строку в Google
Sheets, шлёт уведомление на `submit@cyber-kino-festival.ru` и подтверждение
заявителю.

- `tools/apps-script/Code.gs` — код приёмника, копируется в редактор Apps Script;
- `tools/apps-script/INSTRUCTION.md` — пошаговая инструкция по настройке;
- `assets/js/config.js` — адрес развёрнутого веб-приложения (`endpoint`) и
  ключ `key`, который должен совпадать с `FORM_KEY` в `Code.gs`.

Форма показывается всегда; почтовый путь подачи остаётся рядом как
альтернатива. Обязательны все поля и обе галочки — проверку делает сам браузер
(`required`), а `Code.gs` повторяет её на стороне приёмника, чтобы в таблицу не
попала заявка в обход формы.

Если в `Code.gs` добавляется колонка, список `COLUMNS` правится в одном месте:
скрипт сам допишет шапку в уже существующей таблице. После правки `Code.gs`
нужно заново нажать «Развернуть → Управление развёртываниями → Новая версия»,
иначе Google продолжит выполнять прежний код.

Запрос уходит методом POST с `Content-Type: text/plain;charset=utf-8` — браузер
считает такой запрос «простым» и не шлёт предварительный `OPTIONS`, который
Apps Script не обрабатывает. Тело запроса — обычный JSON.

Заявки из формы уходят на серверы Google за пределы РФ. Поэтому в форме есть
отдельная галочка-согласие на передачу данных в Google, а разделы «Передача
третьим лицам» и «Где обрабатываются данные» в политике конфиденциальности это
описывают. Чтобы перейти на российский приёмник, достаточно поменять `endpoint`:
разметка и скрипт формы не зависят от того, кто принимает запрос.

## Страница 404

`404.html` в корне; Vercel отдаёт её на любой несуществующий адрес. Ссылки в ней
абсолютные — плагин `absoluteNotFoundLinks` в `vite.config.js` переписывает пути
после сборки, потому что страница открывается и по вложенным адресам вроде
`/a/b/c`, где относительные пути не разрешились бы.

## Временные картинки

```bash
pip install pillow
python3 tools/make_placeholders.py
```

Скрипт создаёт заглушку только там, где файла ещё нет, — настоящие картинки он не
трогает. Чтобы перерисовать заглушку, удалите её и запустите скрипт снова.
